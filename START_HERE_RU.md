# GRAND SUPPORT COPILOT — обновление 1.1 · аккаунты и профиль

Прототип для демонстрации кейса Decentrathon 6.0 / Grand Mobile. Код включает локальную модель классификации, приоритеты, RAG по оригинальным правилам, очередь операторов, заметки, назначение, поиск похожих тикетов, массовые действия, экспорт и аналитику. **Это не официальный сервис Grand Mobile и не подключение к реальному API игры.** Отправка игроку, наказания и финансовые операции не выполняются.

## Запуск на Windows (без Docker)

1. Если у тебя уже стоит версия 0.6, **не распаковывай новый архив**. Запусти в существующей папке `UPDATE_PROJECT.bat` и выбери этот ZIP. Локальная база SQLite и настройки сохранятся.
2. Если устанавливаешь впервые: распакуй ZIP один раз, установи Python 3.11–3.13 и Node.js 20+, запусти `setup_windows.bat`.
3. Запусти `start_backend.bat`, затем `start_frontend.bat`. Открой **http://127.0.0.1:5173**.
4. **При первом запуске создай администратора прямо на экране входа**: придумай логин, имя и пароль минимум из 12 символов. После создания аккаунта очередь и API будут требовать вход. Твои старые тикеты в SQLite сохранятся. Если первоначальный экран недоступен, запусти `CREATE_ADMIN_ACCOUNT.bat` в уже установленной папке и создай администратора через консоль.
5. В боковом меню нажми **«Мой профиль»**: изменение имени/email, смена пароля, оформление, компактная очередь, автообновление и уведомления. Администратору доступна вкладка **«Команда»**: создание сотрудников, выбор роли и отключение доступа.
6. Изменения frontend автоматически подхватываются Vite; backend работает с `--reload`. После обновления файлов обычно достаточно Ctrl+F5, но при обновлении Python-зависимостей нужен повторный `setup_windows.bat` и перезапуск backend.

## Запуск через Docker Desktop

В папке проекта запусти `START_DOCKER.bat` или `docker compose up -d --build`. Для Docker первоначальная настройка через браузер по умолчанию отключена (безопаснее для прокси): запусти `docker compose exec api python -m app.bootstrap_cli` и создай администратора в консоли. Интерфейс — **http://127.0.0.1:5173**, API — **http://127.0.0.1:8000/docs**. Обе службы по умолчанию привязаны только к localhost. Для новой сборки повтори `docker compose up -d --build` и обнови страницу. SQLite хранится в отдельном Docker volume.

## Как пользоваться

1. Создай новый тикет или используй демо-сценарий. После анализа тикет появится в очереди.
2. Укажи ответственного, измени статус и приоритет, отредактируй черновик. Запись сохраняется в SQLite.
3. Открой «Совместная работа»: добавь заметку, посмотри похожие обращения, найди первоисточник в базе правил.
4. Для критических кейсов перед завершением **обязательно опиши результат ручной проверки**. Действия оператора логируются.
5. В очереди выбери несколько тикетов, нажми «Взять в работу», «Эскалировать» или «Назначить». Вверху есть экспорт JSONL для резервного копирования тикетов.

## Учетные записи и безопасность

По умолчанию **COPILOT_AUTH_ENABLED=on**. При локальном запуске первый администратор создаётся из интерфейса только при обращении к backend с loopback-адреса. Для Docker или удалённого сервера используй `python -m app.bootstrap_cli`, а `COPILOT_LOCAL_SETUP_ENABLED=0` запрещает веб-настройку. Никогда не публикуй начальную настройку открыто в интернет. В продакшене обязательно нужны HTTPS, внешнее ограничение запросов, управление секретами и аудит безопасности.

- **Администратор** — все действия с тикетами, удаление, добавление и отключение сотрудников, управление ролями.
- **Оператор** — анализ и работа с обращениями, но без удаления и администрирования аккаунтов.
- **Наблюдатель** — только чтение и просмотр, без изменений и запуска анализа.

Пароли хранятся как PBKDF2-SHA256 с индивидуальной солью; сами пароли не сохраняются. Сессии — случайные токены, в базе только SHA-256 хэш токена; срок жизни 12 часов. Смена пароля завершает все сеансы аккаунта. Можно завершить все сеансы вручную во вкладке «Безопасность». Успешные действия оператора по тикетам фиксируются с логином; старым событиям присваивается системный автор. Предпочтения пользователя сохраняются в SQLite и переживают обновление страницы.

**Публичная регистрация закрыта**: после первичного администратора новые аккаунты создаёт только администратор. Отправка писем и сброс пароля по email пока не подключены (поле email справочное). Демонстрационный интерфейс не является официальной системой авторизации Grand Mobile.

## Обновления в той же папке

- `UPDATE_PROJECT.bat` накатывает новый ZIP **поверх установленного проекта**, сохраняет SQLite, `.venv`, `node_modules` и `.env` и создаёт бэкап затронутых файлов в `.copilot-updates/`.
- `UPDATE_FROM_GIT.bat` работает **только после подключения твоего проекта к Git-репозиторию**. Он делает `git pull --ff-only` и не перезаписывает конфликтующие изменения.
- Нажатие F5 **не скачивает новый код само по себе**: для такого сценария нужен настроенный общий сервер/CI/CD с автоматическим развёртыванием. В проект включена проверка GitHub Actions (`.github/workflows/ci.yml`), но публикацию в аккаунте пользователя нужно настроить отдельно.

## Что проверено и что нет

- **43/43 backend-теста пройдены** локально. Проверены миграция SQLite, токен, заметки, назначение, массовые действия, RAG и защита критических обращений.
- Проверены **1000/1000** записей из `tickets_valid.jsonl`; p95 локальной обработки Python около **6.9 мс** на этой машине, без сетевых задержек, при данной конфигурации. 0 некорректных соответствий `(раздел, ref, текст)` найденных источников в этой проверке. Это **не оценка точности классификации**, поскольку в valid отсутствуют независимые метки категорий и приоритетов.
- Новый интерфейс и экраны аккаунтов проверены на синтаксические ошибки средствами TypeScript; **полная установка npm и сборка Vite не подтверждены** в доступной среде (зависимости не скачались). CI собирает frontend там, где доступен npm registry.
- Реальная отправка ответов, доступ к базе Grand Mobile, баны, платежи и автоматический деплой **не реализованы без внешнего доступа и настройки**.

Не загружай настоящие персональные данные игроков в публичный репозиторий. Соблюдай сроки удаления исходного датасета, указанные в конкурсном задании.
