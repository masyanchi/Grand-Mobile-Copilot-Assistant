# Grand Mobile Support Copilot — Submission

## Что сдаём
HTTP-сервис `POST /triage`, пакетный запуск `make predict`, документацию установки и честный отчёт о проведённых проверках.

## Быстрый старт для жюри
1. Скачайте **официальный архив handout** Support Copilot из материалов конкурса. Данные не включены в публичный репозиторий из-за ограничений лицензии.
2. Поместите `rules.json` и `taxonomy.json` в `backend/data/` (именно с такими именами).
3. Установите Python 3.11+ и зависимости: `python -m pip install -r backend/requirements.txt`.
4. Запустите API: `make run` (доступен `http://127.0.0.1:8000/docs`).
5. Отправьте `POST http://127.0.0.1:8000/triage` с JSON-объектом, соответствующим схеме в `/docs`.
6. Пакетная обработка: `make predict IN=/path/to/tickets_valid.jsonl OUT=/path/to/pred.jsonl`.

**Важно:** ML-модели на основе обучающих данных намеренно не включены в публичный репозиторий. Без них сервис работает в режиме детерминированного baseline; обученные веса могут быть предоставлены организаторам приватно при разрешении правилами конкурса. Это значит, что показатели локальной проверки с весами нельзя напрямую приписывать публичной сборке без весов.

## Реализовано
- REST API `/triage` для категории, приоритета, черновика ответа и ссылок на правила.
- Локальный retrieval правил, проверка цитирования, обязательная эскалация платежей, бан-апелляций и угроз аккаунтам.
- `make predict` для JSONL, рабочая очередь оператора, SQLite, авторизация, роли, пользовательские настройки, аудит действий, поиск похожих тикетов и управление черновиками.

## Проверки и метрики (ограничения)
- 45/45 локальных backend-тестов проходили в предыдущем полном пакете с приватными данными.
- В предыдущей пакетной проверке обработаны 1000/1000 обезличенных входов; не обнаружено нарушений соответствия проверенных ссылок на правила. Это **не** независимая проверка релевантности каждой ссылки человеком.
- Ранее наблюдалась p95 локальной обработки около 7,2 мс в конкретном прогоне; это не гарантия и не end-to-end latency через интернет.
- Категория и приоритет тренировались на автоматически созданных слабых метках; точная accuracy/macro-F1 на независимой экспертной разметке **не установлены**.
- Доля `needs_human` в независимом проверочном наборе **не измерена достоверно**; для воспроизводимого расчёта запустите `/triage` на официальном закрытом наборе.
- Стоимость токенов внешних API в текущем локальном inference: **0 USD за запрос**, поскольку внешняя LLM не вызывается; электричество/хостинг не учитываются.
- Полный production-style frontend build в исходной среде не был подтверждён (npm registry недоступен). Backend-тесты не доказывают UX-качество.

## Черновики ответов (иллюстрации, синтетические примеры)
**Платёж:** «Здравствуйте! Чтобы разобраться со списанием и отсутствующим начислением, передаю обращение специалисту по платежам. Пожалуйста, укажите время платежа и ID операции в защищённом канале. Возврат не обещаю до проверки.»

**Жалоба на поведение:** «Здравствуйте! Спасибо за обращение. Укажите ник, сервер, приблизительное время и приложите материалы. Мы проверим обстоятельства по действующим правилам; решение будет принято после рассмотрения.»

**Потеря доступа:** «Здравствуйте! Если вы подозреваете несанкционированный доступ, не отправляйте пароль и коды подтверждения в обращении. Передаю запрос сотруднику для проверки владения аккаунтом.»

Это примеры ожидаемой безопасной формулировки, **не гарантированные фактические ответы модели**.

## Ограничения и безопасность
Настоящие Grand Mobile API и production-инфраструктура не подключены. Не публикуйте `rules.json`, `taxonomy.json`, билеты, Excel/CSV с выборками, SQLite и обученные модели с закрытым происхождением. Воспроизведение оценки требует закрытых данных из официального handout.
